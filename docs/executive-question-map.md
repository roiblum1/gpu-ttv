# Executive question map (E01–E18)

The product contract of AGENT.md §13: each CEO question, the decision it supports, its release (§0.6), the pages and panels that answer it, its data dependencies, capability tier, status and acceptance test. Every panel's full definition (unit, population, window, filters, lineage, unknown-vs-zero behaviour, expected result) is in `config/panel-contracts/<page uid>.yaml`, whose schema is in `config/panel-contracts/README.md`. `tests/test_panel_contracts.py` keeps the contracts, the dashboards and this map in step.

- **Status.** *built*: the R1 page answers the question. *partial*: R1 answers part of it, and the rest waits for a later release or an input. *missing input*: a text card states the exact missing inputs, where they would come from, the onboarding step and the release. It shows no number (§0.6).
- **Tier** (§13 capability tiers). *core*: infrastructure telemetry. *history*: retained ledger history. *business_input*: approved business or planning inputs (§4 "Optional business and planning inputs").
- **Panels** are `uid #id`. For pages built in parallel (Home, Delivery, GPU use, Asset), the panel ids are in that page's contract file.

## Keeping the map true

- A change to a panel updates its contract entry in the same commit (id, title, filters, query, expected result). `tests/test_panel_contracts.py` fails when they drift.
- When a missing-input question is built, replace its text card with real panels, set `status: built` on their contracts and update this table.
- `tests/test_dashboards_sql.py` executes every Postgres query on every page, with All and with one selected value, against a synthetic fixture. Value checks cover §17's numbers.
